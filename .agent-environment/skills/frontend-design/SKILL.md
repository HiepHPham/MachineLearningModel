# Frontend design

Ground the visual direction in the audience, the interface's main job, and the
content that carries that job. Preserve an existing design language when the brief
calls for continuity; use the subject and users to choose a direction when the
brief leaves room.

Develop a compact design thesis: semantic palette, readable type hierarchy,
layout aligned with reading order, and a distinctive detail that serves the
product. Make reasonable choices for a sparse brief and state them briefly.

Build reusable tokens and components. Use composition, spacing, type, and contrast
to communicate hierarchy. Let motion clarify state or orientation. Write copy
with familiar nouns and specific verbs, and test layouts with realistic content.
Match expressive complexity to the product and the framework's maintainability.

Inspect the rendered interface and important interaction states at representative
desktop and mobile sizes. Check reading order, density, overflow, responsive
behavior, and whether the visual direction supports the task. Verify semantic
structure, keyboard operation, visible focus, contrast, and reduced-motion
behavior where motion is present. Iterate from the observed result.
